# VexVPN Connect: руководство для провайдеров

Что приложение VexVPN Connect (iOS) запрашивает у сервера подписки и что понимает в ответе. Документ для
тех, кто настраивает свою панель (Remnawave, Marzban, 3x-ui и другие) или свой сервер под это приложение.
Действует с версии 1.0 (сборка 78).

Приложение — клиент: своих серверов у него нет, и ничего, кроме описанного ниже, оно не отправляет.
Всё, что не указано в документе, приложение игнорирует.

---

## 1. Запрос подписки

Пользователь вставляет ссылку `https://…` (любой хост, порт, путь и query). Приложение делает запрос:

```
GET https://sub.example.com/<путь>?<query>
User-Agent:     VexVPN/1.0/ios/<build>
x-hwid:         <идентификатор устройства>
x-device-os:    iOS
x-ver-os:       26.0
x-device-model: iPhone 17 Pro
Accept:         application/json, text/plain
```

- **Как узнать приложение:** `User-Agent` начинается с `VexVPN/`. Этому клиенту можно отдавать полный
  Xray JSON (раздел 3.1).
- **`x-hwid`** не меняется при переустановке приложения (хранится в Keychain). Переустановка не занимает
  новое место в лимите устройств. После удаления приложения ссылка подписки стирается, HWID остаётся.
- Фрагмент `#…` из ссылки не отправляется. Ссылки `http://` и ссылки с логином в URL (`user:pass@`)
  не принимаются.
- **Редиректы (3xx) не выполняются.** Ответ на 3xx считается ошибкой. Отдавайте подписку по конечному
  адресу.
- Тайм-ауты: 10 с на ответ, 15 с на весь запрос. Тело — не больше 2 МБ.

**Когда приложение запрашивает подписку:** при каждом открытии, при потягивании экрана вниз и кнопкой
обновления (не чаще раза в 5 с), в открытом приложении — не реже раза в час, в фоне — когда разрешит iOS.

## 2. Коды ответа

| Код | Что видит пользователь |
| --- | --- |
| `200` | Подписка разобрана (разделы 3–4). |
| `404` | «Доступ не найден». Подключение заблокировано до новой ссылки или до ответа `200`. |
| `3xx` | Ошибка обновления: редиректы не выполняются. |
| другие | «Не удалось обновить подписку». Остаётся последний успешно загруженный список серверов. |

## 3. Тело ответа

Формат определяется по содержимому, `Content-Type` не важен. HTML (`<…`) — ошибка.

### 3.1. Xray JSON (рекомендуется)

Объект или массив объектов. Каждый объект — отдельный сервер в списке, название берётся из поля `remarks`
(флаг страны в начале названия приложение показывает картинкой). Конфигурация запускается как есть, без
изменений: балансировщики, observatory, routing и DNS работают так, как вы их описали.

Требования (иначе конфигурация отклоняется):

- **`inbounds`:** ровно один `socks` на loopback-адресе (`127.0.0.1` или `::1`), `auth: "noauth"` или без
  `auth`, `udp: true`. Через него приложение передаёт трафик устройства. Дополнительно допускается `http`
  на loopback. Другие inbound, `streamSettings` у inbound и не-loopback адреса не допускаются.
- **Запрещённые разделы верхнего уровня:** `api`, `metrics`, `reverse`, `fakedns`, `browserForwarder`,
  `transport`. Логи в файл не допускаются. Также не допускаются `realitySettings.show: true` и
  `masterKeyLog`.
- **Есть раздел `dns`:** первое правило `routing.rules` — `{"type": "field", "port": 53, "outboundTag": "<тег>"}`,
  где `<тег>` — outbound с `protocol: "dns"`. В первом правиле нет других полей, кроме `type`, `port`,
  `outboundTag`, `balancerTag`. Домены самих узлов должны резолвиться через `dns.servers` с
  `"detour": "direct"` (например, сервер с `"domains": ["full:node-1.example.com"]`).
- **Нет раздела `dns`:** домены узлов резолвит система до подключения. Первое правило не требуется.
- **`geosite:` и `geoip:`:** категории должны быть во встроенных геоданных — это
  [Loyalsoldier/v2ray-rules-dat](https://github.com/Loyalsoldier/v2ray-rules-dat). Неизвестная категория —
  отказ.
- Ядро — Xray-core 26.x.

Минимальный пример:

```json
{
  "remarks": "🇳🇱 Нидерланды",
  "inbounds": [{ "tag": "socks", "protocol": "socks", "listen": "127.0.0.1", "port": 10808,
                 "settings": { "auth": "noauth", "udp": true } }],
  "outbounds": [
    { "tag": "proxy", "protocol": "vless",
      "settings": { "vnext": [{ "address": "nl.example.com", "port": 443,
                                "users": [{ "id": "<uuid>", "encryption": "none", "flow": "xtls-rprx-vision" }] }] },
      "streamSettings": { "network": "tcp", "security": "reality",
                          "realitySettings": { "serverName": "www.example.org", "publicKey": "<pbk>",
                                               "shortId": "<sid>", "fingerprint": "chrome" } } },
    { "tag": "direct", "protocol": "freedom" }
  ]
}
```

### 3.2. Список ссылок серверов

Обычный текст или base64 (стандартный или URL-safe, с `=` или без): по одной ссылке на строку, до 512
строк. Строки неподдерживаемых форматов (hysteria2, tuic, wireguard и другие) пропускаются. Если не
разобралась ни одна строка, показывается ошибка первой строки. Название сервера — фрагмент `#…`
(для vmess — `ps`).

Для ссылок приложение само строит конфигурацию: loopback SOCKS → outbound ссылки, домен сервера резолвит
система. Своих DNS и routing у такой конфигурации нет. Если они нужны, отдавайте Xray JSON (3.1).

| Протокол | Поддерживается |
| --- | --- |
| `vless://uuid@host:port?…#имя` | `encryption=none`; `flow=xtls-rprx-vision` или `xtls-rprx-vision-udp443` |
| `vmess://base64(JSON)` | формат v2rayN; только AEAD (`aid=0`); `scy`: `auto`, `aes-128-gcm`, `chacha20-poly1305`, `none`, `zero` |
| `trojan://password@host:port?…#имя` | по умолчанию `security=tls` |
| `ss://…#имя` | SIP002 и старый base64-формат; методы `aes-128-gcm`, `aes-256-gcm`, `chacha20-(ietf-)poly1305`, `xchacha20-(ietf-)poly1305`, `2022-blake3-aes-128-gcm`, `2022-blake3-aes-256-gcm`, `2022-blake3-chacha20-poly1305`, `none`. Плагины (`plugin=`) не поддерживаются |

Параметры транспорта (`type=`, для vmess — `net`):

| `type` | Параметры |
| --- | --- |
| `tcp` / `raw` (по умолчанию) | `headerType` только `none` |
| `ws` | `path` (по умолчанию `/`), `host` |
| `grpc` | `serviceName`, `mode=multi`, `authority` |
| `httpupgrade` | `path`, `host` |
| `xhttp` / `splithttp` | `path`, `host`, `mode` (`auto`, `packet-up`, `stream-up`, `stream-one`), `extra` (JSON) |

Параметры защиты (`security=`):

| `security` | Параметры |
| --- | --- |
| `none` (по умолчанию для vless) | — |
| `tls` | `sni` (или `peer`), `alpn` через запятую, `fp`. Без `sni` проверяется `host` или домен сервера |
| `reality` | обязательны `sni` и `pbk` (43 символа, 32 байта); `sid` — hex, до 16 символов; `spx`; `fp` (по умолчанию `chrome`) |

`fp`: `chrome`, `firefox`, `safari`, `ios`, `android`, `edge`, `360`, `qq`, `random`, `randomized`. Другие
значения и неизвестные `type` / `security` — отказ по этой строке с названием параметра. Другие
неизвестные параметры игнорируются.

### 3.3. Отказ в доступе телом («заглушка»)

Чтобы показать пользователю причину отказа (срок закончился, устройство не зарегистрировано), отдайте
`200` с сервером по адресу **`0.0.0.0`, порт `1`**:

- в JSON — outbound с `vnext[].address: "0.0.0.0"` и `port: 1`, текст — в `remarks`;
- в списке ссылок — ссылка на `0.0.0.0:1`, текст — во фрагменте `#…`.

Если заглушка есть хотя бы в одной строке или объекте, весь ответ считается отказом. Подключение
блокируется. Текст `remarks` / фрагмента в интерфейсе не показывается: приложение пишет своё короткое
«Провайдер закрыл доступ» (или «Доступ закончился» / «Трафик закончился», если это следует из
`subscription-userinfo`).

## 4. Заголовки ответа

Значения заголовков — ASCII. Для текста на русском и эмодзи используйте `base64:` + base64 от UTF-8.

| Заголовок | Значение | Как показывается |
| --- | --- | --- |
| `profile-title` | текст или `base64:…` | Название подписки в «Настройках» и заголовок окна сообщения. Некорректный `base64:` — ошибка всей подписки |
| `subscription-userinfo` | `upload=…; download=…; total=…; expire=…` (байты, unix-время) | `expire` — строка «Доступ действует до …», в последние сутки — «ещё N ч M мин»; `expire=0` — бессрочно; без `expire` строки нет. `total>0` — остаток трафика в мини-блоке шапки, по нажатию — «Осталось X», «Израсходовано Y из Z»; `total=0` — безлимит, строки нет |
| `profile-web-page-url` | `https://…` | Кнопка «Личный кабинет» (открывается в Safari) |
| `support-url` | `https://…` | Кнопка «Поддержка» (открывается в Safari) |
| `x-vex-devices` | `занято/лимит`, например `2/5` | Строка «2/5» в мини-блоке шапки, по нажатию — «Устройства: 2 из 5» и число свободных мест. Некорректное значение игнорируется |
| `x-hwid-limit` | `true` | «Лимит устройств исчерпан». Подключение блокируется, даже если тело пустое или нечитаемое |
| `announce` | текст или `base64:…`, до 1000 символов | Окно сообщения (раздел 5) |
| `announce-interval` | целое число часов, 1–720; по умолчанию 24 | Как часто окно появляется снова после «Понятно» |
| `profile-update-interval` | часы | Читается, но интервал обновления не бывает больше часа |

Ссылки `http://`, `javascript:` и с логином в URL игнорируются: кнопка не появляется. Надписи кнопок
задаёт приложение, провайдер их не меняет.

**Не используются:** `sub-expire`, `sub-expire-button-link`, `fallback-url`, `check-url-via-proxy`,
`x-hwid-active`, `routing`, `mux-enable`, `content-disposition`. Некорректный `base64:` в `announce`
не ломает подписку: сообщение просто не показывается.

## 5. Окно сообщения провайдера

Текст `announce` и `profile-title` приложение очищает: разметка (HTML, Markdown) не обрабатывается и
показывается как есть; управляющие и невидимые символы, смена направления текста удаляются; больше двух
диакритик на букву, повторные пробелы и пустые строки сокращаются; `profile-title` — до 80 символов.

Заголовок `announce` (тот же, что у других Xray-клиентов) показывает пользователю окно: заголовок — `profile-title` (или «Сообщение
провайдера»), текст как есть (ссылки не активны), две кнопки:

- **«Понятно»** — окно появится снова через `announce-interval` часов;
- **«Скрыть на 24 ч»** — окно не появится весь срок, который пользователь выбрал на странице провайдера
  («Настройки → Подписка → <название>» → «Пауза сообщений»): 24 часа (по умолчанию), 3 дня, неделя или месяц.

Новый текст сообщения показывается сразу, даже во время паузы. Пользователь может выключить окно совсем
(там же, «Сообщения провайдера»); тогда сообщение доступно только по кнопке (i). По (i) сообщение
открывается выпадающим окошком без кнопок и расписание не меняет. Окно появляется только на открытой главной
странице, не поверх других окон. Кнопка **(i)** в шапке рядом с кнопкой обновления открывает окно в любой
момент; её нет, пока провайдер не передаёт `announce`. Чтобы убрать сообщение, перестаньте отправлять
заголовок.

Пример (текст «Плановые работы 25.09 с 03:00 до 04:00», показывать раз в 6 часов):

```
announce: base64:0J/Qu9Cw0L3QvtCy0YvQtSDRgNCw0LHQvtGC0YsgMjUuMDkg0YEgMDM6MDAg0LTQviAwNDowMA==
announce-interval: 6
```

## 6. Кнопка «Добавить в VexVPN» на вашем сайте

```
vexvpn://import?url=<ссылка подписки https, URL-encoded>
vexvpn://import?link=<ссылка сервера vless/vmess/trojan/ss, URL-encoded>
```

Приложение спрашивает «Добавить подписку? Источник: <хост>» и ничего не делает без подтверждения. Если
подписка уже есть, она заменяется, VPN отключается. Сами по себе такие ссылки VPN не включают.

## 7. Проверка

1. Откройте ссылку подписки с `User-Agent: VexVPN/1.0/ios/78` и любым `x-hwid` и убедитесь, что приходят
   `200`, нужное тело и заголовки:

   ```sh
   curl -sD - -A 'VexVPN/1.0/ios/78' -H 'x-hwid: test-device' 'https://sub.example.com/<путь>'
   ```

2. Вставьте ссылку в приложение: должны появиться список серверов, пинг и подключение.
